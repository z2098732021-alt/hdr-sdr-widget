# 0.5.0：胶囊折射优化、DDC/CI 与 SDR 软件压暗

## 更新内容

- 参考手机音量条，调整连续凸面折射：加强两侧与上下圆弧的弯曲、局部放大，保持中部文字与网格清晰。保留现有胶囊尺寸、拖动交互、动画和 HDR 白色液位。
- 新增 DDC/CI 硬件亮度控制（VCP `0x10`），启动时只读检测，不通过试写改变显示器亮度。写入按设备报告范围换算并回读确认。
- 默认自动选择：HDR 开启时调节系统 SDR 内容亮度；SDR 下优先使用 DDC/CI，不可用时自动使用软件压暗。
- 托盘新增按显示器记忆的控制方式菜单、实际生效方式、降级原因、重新检测和恢复所有屏幕的软件亮度。
- 软件压暗采用鼠标穿透、不抢焦点的独立遮罩。滑条 100% 无压暗，50% 约为 45% 黑色遮罩，0% 约为 90% 黑色遮罩；最低仍保留约 10% 透光。隐藏胶囊不取消压暗，退出移除遮罩，每次启动从无压暗开始。
- 亮度服务独立于原生/旧版渲染器，各显示器独立处理请求。DDC 最小写入间隔 100ms，合并连续请求并确认最终值；连续失败或超时后回退，未返回的驱动调用不再叠加。
- 修复 Windows 自动色彩管理（WCG）被误判为 HDR：优先读取实际高级色彩模式，旧系统保留兼容查询。
- 将 HDR 色彩状态、亮度后端及可调节状态分离，DDC 原始值不再参与 HDR 白点换算，SDR 可调节时不显示错误的 HDR 警告点。

## 使用与兼容

右键托盘 → **亮度控制方式 → 显示器 → 自动 / HDR SDR 内容亮度 / DDC/CI 硬件亮度 / 软件压暗**。

手动方式不可用时回退到可用方式，菜单保留所选偏好并显示实际方式。不同后端的百分比不代表同样的物理亮度，因此切换后读取新后端当前值，进入软件压暗从 100% 开始。DDC 与软件模式不显示未经校准的 nits。

配置格式升级至 v3，兼容现有设置、位置与预设。只新增每显示器控制偏好，不保存或恢复软件遮罩强度。检测失败时，可检查显示器 OSD 的 DDC/CI 开关后点击“重新检测显示器控制能力”。

## 验证

- 109 项 Rust 测试通过，包含 HLSL 编译、后端选择、过期请求隔离、DDC 范围换算、超时后迟到回复隔离和配置迁移；TypeScript 检查与 Vite 构建通过。
- 本机 Mi Monitor 的 DDC/CI 亮度读取失败，已验证检测失败的处理路径。**本次没有支持 DDC/CI 的显示器完成硬件写入成功实测**，不将逻辑测试等同于硬件兼容性验证。
- 软件压暗集成检查覆盖无写入切入、0/50/100%、连续 1000 次请求后的最终值、恢复与返回自动模式；读取实际 Win32 窗口透明度、可见状态、鼠标穿透、不激活及捕获排除标记。
- 已在本机实际关闭 HDR，验证 SDR → DDC/CI 不可用 → 软件压暗，七项控制检查通过；测试结束恢复 HDR，SDR 内容亮度仍为原来的 15%（raw 1750）。
- 已保存“软件压暗”控制偏好后重新启动，确认仍从 100%／无压暗开始。
- WGC FP16、DDA 捕获、旧版前端启动和 HDR 白色液位回归通过。HDR 白点为 140 nit 时，浮点读回液位主体约 673–675 nit；这是 scRGB 数值换算，不是光度计测量。
- 折射对比使用同一 GPU、同一图卡与照明，对照旧/新折射模型，覆盖网格、同心圆、棋盘格、条纹和文字。PNG 仅用于 SDR 外观对比，HDR 白色液位另外用浮点读回数据检查。

DDC/CI 是否可用取决于显示器、OSD 设置、显卡驱动和连接路径。镜像拓扑无法唯一绑定物理显示器时不猜测硬件目标。软件遮罩不改变显示器背光，独占全屏、安全桌面及特殊受保护内容不保证覆盖；不同显卡、混合 DPI、多屏热插拔和真实睡眠恢复仍需更多实机覆盖。

## 复测与构建

在 `src/hdr_sdr_widget` 目录执行：

```powershell
npm run build
cargo test --manifest-path src-tauri/Cargo.toml --lib --bin hdr-sdr-widget
pwsh -NoProfile -File scripts/build.ps1
pwsh -NoProfile -File scripts/qa-native.ps1 -Mode Brightness -Seconds 25 -OutputDirectory ../../deliverables/v0.5.0/qa/brightness
pwsh -NoProfile -File scripts/qa-native.ps1 -Mode OpticsBaseline -Seconds 22 -OutputDirectory ../../deliverables/v0.5.0/qa/optics-before
pwsh -NoProfile -File scripts/qa-native.ps1 -Mode Optics -Seconds 22 -OutputDirectory ../../deliverables/v0.5.0/qa/optics-after
cargo run --manifest-path src-tauri/Cargo.toml --bin probe_control -- read
```

`probe_control sdr-audit <程序路径> <输出目录>` 是显式的实机测试入口：短暂关闭第一台显示器的 HDR，启动独立配置的亮度审计，完成后恢复原 HDR 状态。正常应用启动不会自动开关 HDR。
